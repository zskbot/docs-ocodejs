01 / Tổng quan

Một điểm vào. Toàn bộ hệ sinh thái.

OCode.js hướng tới việc đơn giản hóa cách xây dựng ứng dụng web bằng JavaScript và TypeScript. Trang tài liệu này là lớp điều hướng chung; chi tiết triển khai cần được đối chiếu với mã nguồn và phiên bản thực tế.

⌘

Developer-first

Tập trung vào cấu trúc dễ hiểu, quy trình phát triển mạch lạc và tài liệu có thể tra cứu nhanh.

◈

Web application

Định hướng tổ chức ứng dụng theo tuyến trang, thành phần giao diện và lớp xử lý phía máy chủ.

✳

JavaScript + TypeScript

Thiết kế hướng tới hệ sinh thái JS/TS; kiểm tra API và khả năng tương thích theo phiên bản trước khi phát hành.

02 / Bắt đầu

Bắt đầu từ mã nguồn

Dùng repository chính để kiểm tra các script, dependencies và hướng dẫn mới nhất. Không giả định tên lệnh chạy khi chưa xác minh package hiện tại.

Terminal
# Lấy mã nguồn
git clone https://github.com/Velclaw/OCodejs.git
cd OCodejs

# Cài dependencies theo package manager của dự án
npm install
ⓘ

Lưu ý: Các lệnh trên là điểm khởi đầu phổ biến cho repository Node.js. Hãy xác nhận package.json, lockfile và README trước khi chạy; không dùng ví dụ này thay cho quy trình phát hành chính thức.

STEP 01

Khám phá

Đọc README và cấu trúc thư mục để xác định entry point, scripts và yêu cầu runtime.

STEP 02

Kiểm chứng

Chạy test, lint và build được khai báo trong package.json trước khi sửa đổi.

STEP 03

Phát triển

Tạo nhánh riêng, thay đổi theo phạm vi nhỏ và mở pull request để review.

05 / Routing & rendering

Quy ước phải rõ ràng

Khi mở rộng framework, giữ một nguồn sự thật cho hành vi routing và rendering để tránh tài liệu lệch khỏi mã nguồn.

06 / API & module

Tài liệu API có thể kiểm chứng

Mỗi API nên ghi rõ chữ ký, kiểu dữ liệu, giá trị trả về, lỗi có thể phát sinh, ví dụ chạy được và phiên bản áp dụng.

NhómPhạm vi tài liệuGợi ý kiểm thử
HTTPRequest, response, timeoutNetwork error, timeout, status code
AsyncPromise, retry, cancellationResolve/reject, race conditions
URLParse, normalize, query paramsUnicode, encoding, malformed URL
ValidationInput constraints, error formatBoundary cases, invalid values
⚑

Nguyên tắc phát hành: Không ghi một module là “ổn định” hoặc “đã hỗ trợ” cho đến khi có implementation, test và tài liệu tương ứng.
